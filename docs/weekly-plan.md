# PhaseMend 每周计划与检验清单

本计划依据项目负责人提供的课程研究方案 v1.0，将 [README](../README.md) 中的路线拆为 12 周可检查的任务。所有任务初始均为待完成；W1 从实际开工起算，不据仓库创建日期推定项目进度。定量指标均为目标。

## 使用方法与共同完成标准

每周按“先复跑上周基线 → 完成本周最短闭环 → 固定配置验收 → review”推进。每周至少保留一段可运行 demo 和一个可复现运行入口；正式汇报在 W2 / W4 / W6 / W8 / W10 / W12。

周末交付包需包含：代码 commit、环境 / 资产 / checkpoint 标识、YAML 配置、随机种子、原始日志、指标摘要、一段连续视频、通过项与未通过项、下一周决定。可以使用 `reports/Wxx/` 保存这些材料；该目录与下文命令入口均为待实现约定。

“完成”要求有证据。未达到门槛时写明实际值和原因，不将已知失败从统计或视频中隐藏。周报统一使用以下记录格式：

| 项目 | 填写内容 |
|---|---|
| 验收日期 / 周次 | 实际时间与 Wxx |
| 复现依据 | commit、配置、环境、权重、数据版本、运行命令 |
| 结果 | 指标实际值、样本数、通过 / 未通过 |
| 证据 | 原始日志、表格、图、连续视频路径 |
| 资源 | GPU 小时、显存峰值、运行时间 |
| 决定 | 继续 / 限时修复 / 启动替代路线及原因 |

## W1：确定可运行的技术地基

**目标：在投入训练前确认资源可用，消除接口与时间口径歧义。**

- [ ] 记录主机 OS、驱动、GPU / 显存、Python、CUDA 与仿真器版本；训练后端如需其他运行环境，记录实际选择及依赖。
- [ ] 加载目标 G1 资产，核对 29 DoF 配置、关节名称 / 顺序、坐标系、单位、惯量、限位和 PD 参数。
- [ ] 对至少两个追踪起点做兼容性检查：机器人构型、观测、参考格式、动作含义、归一化、训练后端、checkpoint 可获得性与许可。
- [ ] 确认一条实际可访问的数据路径；需要申请访问的数据登记申请状态。BABEL 等依赖其他数据的资源不得作为未经验证的独立退路。
- [ ] 写最小 EMB / DSL 字段草案：时间锚点、采样率、位姿、根状态、接触、相位、部位掩码、版本、请求 ID、超时与取消。
- [ ] 分别定义保护前瞻、修复窗口、参考预览窗口、控制周期；记录 200 ms 前瞻与 150 ms 可见响应目标冲突，提出配置 / 目标选择并保留决策状态。
- [ ] 短程测量候选推理和仿真吞吐，估计训练预算；不直接按原文各模块估算相加安排 GPU 时间。

**交付：**静态 G1 demo、环境记录、依赖 / 权重兼容表、数据访问表、接口草案、时间口径与资源预算记录。

**检验：**新进程可按记录加载 G1 并完成固定步长仿真，无 NaN；至少一个追踪起点有明确的可用路径，或已说明阻碍并选择最小替代范围。时间冲突如果尚未决策，必须作为阻塞项保留，不能标为已解决。

## W2 · R1：跑通数据到开环动作播放

**目标：能把真实参考动作转换并在 MuJoCo 中播放。**

- [ ] 建立数据清单和动作 ID，记录许可、帧率、原始骨架及训练 / 验证 / 测试划分。
- [ ] 完成至少一条数据解析 → 坐标统一 → FK / IK 重定向 → G1 参考导出的管线。
- [ ] 导出关节、根位姿、接触 / 相位等字段；记录缺失字段的估计方式。
- [ ] 显示足部、关键点、参考根轨迹，定位脚滑、穿地、关节饱和及重定向误差。
- [ ] 建立 20 项文献核查表：原论文 / 官方仓库、能力、checkpoint、机器人 / 数据特征、许可、已核查或待核查状态。

**交付：**一段 ≥10 s 的开环播放视频、重定向脚本与配置、输入 / 输出样例、文献矩阵、R1 材料。

**检验：**同一输入与配置可重复导出；无 NaN、帧数 / 时间戳单调、关节目标符合所选限位策略；开环视频明确标注开环，不以它证明物理稳定性。

**R1 要回答：**具体研究哪一段接口问题？现有工作分别提供什么能力，哪些边界仍待核查？

## W3：接入无编辑追踪器

**目标：先建立可靠的普通追踪基线。**

- [ ] 载入已选 checkpoint，核对观测与动作映射、归一化、关节偏置、PD、控制频率与参考预览。
- [ ] 接通 MuJoCo 状态 → policy → PD → 仿真的闭环。
- [ ] 如策略在其他仿真器训练，记录资产与动力学差异，单独复现和定位 sim-to-sim 问题。
- [ ] 自动记录根误差、关键点误差、接触、摔倒、策略 / 仿真耗时及显存。
- [ ] 固定第一组验收动作与随机种子，保存无编辑结果。

**交付：**单动作闭环 demo、适配记录、评测日志与基线曲线。

**检验：**至少一段动作连续追踪 ≥10 s 不摔，误差可自动计算；同配置复跑能够生成相同结构的结果。尚不要求本周达到最终精度指标。

## W4 · R2：形成追踪器 v1

**目标：用 3–5 段动作证明可稳定追踪，再投入编辑模块。**

- [ ] 对站立、慢走和上半身动作建立 3–5 段固定验收集；测试动作与微调训练动作分离。
- [ ] 仅在需要时微调策略，保留原 checkpoint 及每轮 GPU 时间、回报、误差和失败日志。
- [ ] 明确根位置误差、全身 MPJPE 与摔倒判据，不通过逐帧根对齐掩盖根漂移。
- [ ] 固定普通追踪 checkpoint，作为 edit-robust 对照起点。

**交付：**checkpoint、3–5 段闭环视频、根误差 / 摔倒率曲线、R2 材料。

**检验：**预先登记的验收动作均有连续 ≥10 s 不摔的闭环演示，根位置平均误差 <15 cm；同时提交重复运行统计，不能用单次成功替代稳定性统计。

**红线：**无法持续追踪 10 s 时，先缩至 Plan B1：站立 / 慢走 + 上半身编辑；追踪器仍不可用再评估 Plan B2：IK + 平衡补偿。替代控制仍须闭环验证，不预设其稳定。

**R2 要回答：**普通动作能否跟上，误差和失败主要在哪里？

## W5：冻结 EMB v1 和基础编辑事务

**目标：编辑能被准确表达、隔离、验证和撤销。**

- [ ] 实现环形缓冲、历史保护、未来窗口、候选副本、提交 / 取消及版本快照。
- [ ] 固定字段、形状、单位、坐标系、旋转约定、时间锚点和接触 / 相位采样规则。
- [ ] 给六类算子建立统一接口与合法性校验；先实现确定性变速、根 / 末端约束和幅度修改，生成部分可用替身输入联调。
- [ ] 为 `replace` / `inpaint` 接入真实候选保留接口；尚未实现的能力明确标记。
- [ ] 验证越界窗口、未知部位、非法数值、过期版本、同时请求、取消和撤销语义。

**交付：**EMB / DSL 基础 schema、离线编辑入口、版本与撤销 demo、代表性输入 / 输出。

**检验：**编辑前后已执行前缀保持不变；候选生成不改变执行缓冲；非法请求产生可读错误；撤销只改变未来计划；旧版本候选无法覆盖当前版本。绕过生成器时，EMB 可独立运行。

## W6 · R3：实现局部修复和离线可执行编辑

**目标：固定上下文后，生成满足编辑约束的可追踪片段。**

- [ ] 先跑通候选生成模型的官方特征输入，再实现 EMB 特征适配并测量往返重建误差。
- [ ] 接入固定前缀、软后缀、部位掩码和硬约束；记录采用的少步采样 / 蒸馏方式及训练预算。
- [ ] 用固定样例展示六类算子，报告生成、几何 / 运动学筛查与闭环执行之间的差异。
- [ ] 在调参前冻结 60 个离线编辑请求，每类算子 10 个；预设容差与超时。
- [ ] 对 E1–E3 各至少 10 个代表请求进行闭环回放，验证“几何可行”不被直接当作“可执行”。

**交付：**局部修复 demo、模型与适配配置、60 请求结果表、闭环回放视频、R3 材料。

**检验：**冻结请求集硬约束满足率 >70%，前缀正确保留；代表性编辑片段能被闭环执行，并报告全部回放中的摔倒率和失败案例。统计满足率时拒绝、超时和无输出均算失败。

**红线：**满足率 <60% 时改走测试时优化修复路线；60%–70% 时标记未通过，限时修复并暂缓扩大语义范围。该替代针对生成 / 修复模块，不等同于放弃追踪控制器。

**R3 要回答：**编辑约束能满足多少，满足几何约束后是否仍会摔倒？

## W7：在线接管与 edit-robust 训练

**目标：编辑过程持续运行控制回路，候选通过受控方式接管。**

- [ ] 接通执行 / 候选双缓冲、相位偏移搜索、有效旋转插值与 overlap 混合。
- [ ] 实现 commit 门控、最多 3 个控制周期的重试、拒绝 / 降级和参考限速器候选配置。
- [ ] 异步短 rollout 带候选版本、状态时间戳和超时；拒绝迟到或失效的预演结果。
- [ ] 注入慢生成、失败、断连、连续请求和撤销，验证控制仍获取有效参考。
- [ ] 从 W4 起点训练 edit-robust 策略，加入时间扭曲、拼接、future dropout 和 0.2 s 参考冻结；保留同预算普通训练对照。

**交付：**E1–E3 在线 demo、门控 / 拒绝 / 失败恢复日志、策略对比初版。

**检验：**慢生成和失败不阻塞主循环；候选从提交前到提交后时间单调；相位不兼容时不强制切换；过期候选不能覆盖新编辑。记录实际控制周期超限率，不能仅凭目标频率声称控制实时。

## W8 · R4：在线 MVS 验收

**目标：用连续录屏与真实时间戳证明实时编辑，而非分段播放。**

- [ ] 固定 E1–E3，每场景至少 20 次 episode，每次编辑后持续观察 ≥10 s；冻结请求时刻和种子。
- [ ] 保存输入、DSL、候选、commit、机器人状态与展示时间戳；区分首次粗响应和完整请求生效。
- [ ] 完成 P50 / P95、根误差、足滑、穿地、约束满足率、jerk 与摔倒率汇总。
- [ ] 初步复现 Baseline-1 硬切换、Baseline-2 crossfade，比较相位对齐 / edit-robust 的实际收益。
- [ ] 录制一段不剪辑的 E1–E3 连续键盘 / DSL 编辑视频，展示实时输入与状态。

**交付：**MVS、连续视频、原始时间戳、分段延迟表、完整指标表、R4 材料。

**检验：**端到端 P95 <350 ms；连续验收演示的 E1–E3 全部可编辑且不摔；重复测试摔倒率 <10%；按 README 的最终目标同时检查根误差 <8 cm、足滑 <5 cm/s、超容差穿地帧为 0、硬约束满足率 >85%、jerk 峰值 < crossfade 的 50%。全部指标公开实际值，未达标项不能勾选通过。

P50 <150 ms 仍按 W1 的时间决策验收；如保护前瞻冲突尚未解决，明确标为未通过，不能用候选延迟替换。后续自然语言模式另行计时，不能直接继承键盘延迟结果。

**红线：**P95 为 350–500 ms 时暂停扩展，修复瓶颈；>500 ms 或稳定性持续失败时缩至键盘 / DSL + 上半身范围，仍失败再启用 Plan B3：编辑—预演—播放。LLM 已异步时，移除 LLM 不能代替对快速路径的优化与重测。

**R4 要回答：**用户输入到实际动作变化到底多久，失败率多高？

## W9：完成语义编译与异步协议

**目标：将自然语言转换为可验证、可执行的编辑请求。**

- [ ] 依据实测显存选择本地模型规模；记录量化、推理配置与上下文大小。
- [ ] 实现状态摘要、结构化输出、schema 校验、最多 2 次解析重试及错误回灌。
- [ ] 实现快速代理 → 后台精确解析 → 平滑修正，防止旧语言结果覆盖较新请求。
- [ ] 实现 LLM → 模板 / 槽位 → 快捷键的降级，并记录触发原因。
- [ ] 冻结至少 100 条独立评测指令，覆盖 E1–E6、同义表达、组合编辑、时间指代、不可行 / 含糊请求；不与提示词示例重复。

**交付：**语言 demo、指令集和人工标注、编译输出、版本 / 降级日志。

**检验：**JSON 合法与语义正确分开计数；非法或越权窗口请求不能执行；断开 LLM 后模板 / 键盘路径仍能使用；模糊请求不得被无记录地转为任意强约束。一般语言请求的 LLM 等待计入端到端时间。

## W10 · R5：验证语言价值与可用性

**目标：证明语言接口的收益，并检查异步响应是否真正改善体验。**

- [ ] 在独立指令集比较 LLM 与模板，分别报告结构合法率、字段 / 时间 / 部位语义正确率和最终执行成功率。
- [ ] 比较乐观异步与同步等待，报告快速代理命中率、粗响应偏差、最终修正耗时和降级率。
- [ ] 组织目标 n=10 的固定任务研究，收集完成率、SUS 和“响应及时”1–5 分评分。
- [ ] 汇总 E1–E6 的文本、键盘、撤销及错误恢复演示，保留失败案例。

**交付：**语言 / 模板消融、异步消融、用户研究初版、R5 材料。

**检验：**NL→DSL 语义成功率 >85%；“响应及时”均分 >4/5；任务完成率 >80%、SUS >70 为计划目标；实际人数、条件和全部结果可追溯。

**红线：**无法组织 n=10 时执行作者评估 + 3 人小样本并说明限制；若仍不足则报告实际人数，不扩写为目标样本量。语言可靠性不足时缩至模板支持的命令范围。

**R5 要回答：**LLM 比模板多解决了什么，付出了多少延迟和失败成本？

## W11：完成正式对照与消融

**目标：用统一评测支撑研究结论。**

- [ ] 完成 Baseline-1 硬切换、Baseline-2 crossfade、Baseline-3 MotionLCM 式流式重生成、Baseline-4 无编辑参考。
- [ ] 记录 Baseline-3 使用官方实现还是自建适配、checkpoint、采样步数和改动；未能复现时明确标注缺项，不用更弱替身冒称已复现。
- [ ] 完成五组消融；普通 / edit-robust 策略使用相同初始权重和训练预算。
- [ ] 正式评测每个适用“场景 × 方法”至少 20 次独立 episode，配对使用动作、请求时刻和种子。
- [ ] 对接管算法先固定同一追踪器 / 候选生成器隔离比较，再报告完整系统组合收益。
- [ ] 生成均值、分位数、样本数及合理的不确定性统计；整理足滑、相位错配、不可达约束、过期候选等失败案例。

**交付：**正式原始日志、结果总表、图、消融表、失败案例与资源开销表。

**检验：**适用组合均有可追溯结果；无编辑参考的编辑指标标为 N/A；基线预算、数据隔离和失败分母经过检查；不预设 Ours 必然获胜，负结果同样写入报告。

## W12 · R6：复现与最终交付

**目标：他人能理解、运行并核查系统和主要结论。**

- [ ] 冻结代码、配置、checkpoint 标识与评测清单，完成干净环境的 demo 复跑。
- [ ] 提供环境安装、资产 / 数据获取、权重获取、最小 demo、完整评测、图表生成的真实命令。
- [ ] 一条命令从冻结的原始结果重建全部图表；训练、完整仿真评测和仅出图分别注明耗时与依赖。
- [ ] 在冻结配置下执行一次完整评测入口；可用 W11 的正式运行作为证据，不为交付重复无必要的昂贵训练。
- [ ] 完成 PDF 报告、连续演示视频、代码 zip、已知限制与复现说明；检查外部资产再分发条件。
- [ ] 报告至少用 3 项实测指标支撑主要结论，列出未达标目标及缩范围记录。

**交付：**最终系统与全部材料、R6 汇报。

**检验：**按文档从干净环境可完成最小 demo；图表可从原始日志自动重建；代码、配置和报告数值一致；报告明确区分已实现、部分实现和未完成项。

**R6 要回答：**哪些机制带来可重复收益，哪些场景仍失败，下一步研究应聚焦什么？

## 统一评测口径

这些口径需在对应实验开始前落实到配置并冻结；变更时保留版本与原因。

| 项目 | 约定 |
|---|---|
| 时间轴 | 仿真时间描述运动与约束；单调墙钟测量交互延迟；显式记录二者映射 |
| 请求时刻 | 收到完整文本 / DSL / 键盘事件时打点；相对时间统一锚定此刻 |
| 延迟分解 | 收到请求、DSL 就绪、候选就绪、commit、首次有效状态变化、完整约束满足、展示时刻分别打点 |
| 可见响应 | 对应请求的有效动作变化；UI “已收到”提示不算机器人动作响应。若仅测到状态 / 渲染代理时间而非真实展示，明确代理口径 |
| 异步粗响应 | 首次粗响应和完整语义生效分别报告；不支持的语言意图不得沿用规则命中请求的延迟 |
| 分位数 | 明确预热次数和有效样本数；冷启动另报；端到端分位数独立统计，不相加模块分位数 |
| 拒绝 / 超时 | 计入编辑任务失败；无有效响应时标记失败而非伪造延迟；另报成功条件下的延迟及全部请求的超时 / 截止期违约率 |
| 约束满足率 | 一条请求的全部硬约束在规定窗口和容差内满足才算成功；拒绝、超时、无输出均在分母内 |
| 追踪误差 | 根位置误差使用固定世界 / 初始对齐约定；根对齐全身 MPJPE 单列，不能抵消根漂移 |
| 足滑 / 穿地 | 先冻结接触标签、支撑帧、地面高度和数值容差；足滑仅在支撑期间统计，同时保留全帧记录 |
| 摔倒 | 用根高度、躯干倾角、非预期身体接触等组合确定适用阈值；episode 时长和重置规则一致 |
| 平滑性 | jerk 使用相同坐标系、采样率、滤波及交接窗；同时检查普通追踪本底噪声 |
| 公平性 | 同动作、请求、时刻、种子与评测时长；每次只改消融因素；报告训练 / 推理预算 |
| OOD | 测试动作与指令不进入训练或提示样例；是否属于 OOD 由具体划分证明 |
