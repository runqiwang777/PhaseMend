# A/B 重复与耐久验证：本轮未放行真人物理接入

2026-11-19。本轮严格按“起点重复 → 耐久 → 真人抬手和下蹲 → 逐级扩大幅度”设置出口。结果是：**新参考范围中的独立静态站立检查通过，但动态耐久未通过；真人物理接入和幅度扩大均未开展。** 本报告不表示三个阶段已经全部完成。

十次各 60 秒、动态耐久 648 秒及相应阈值，是本轮预先登记的工程门槛，不是附件 PDF 原文规定的数字。

本轮共归档 20 次物理尝试，包括筛查、诊断和固定批次；它们的参考条件、初始化流程不同，不能合并成同一算法成功率。汇总脚本错误修复后，v3 首次 A 没有重跑，只从已保存日志重算并继续原批次，因此没有额外增加物理尝试。

十次静态站立的约 600 秒不能算作要求的动态耐久时间。A 的动态耐久实际覆盖左臂模式约 108 秒、右臂模式约 37 秒；双臂模式和 B 起点耐久都未到达。既不能说“648 秒通过”，也不能说“三种模式全部通过”。

## 原 B 和新 B 必须区分

原 A 是从已有步行参考的首帧固定出来的站立参考；原 B 在同一腿部和腰部参考上，对两侧肩俯仰各减 0.15rad、肘角各加 0.20rad。它们此前的短片段成功没有充分证明长期站立及持续编辑的可执行性。

原 B 在本轮出现一次实际摔倒、一次漂移保护退出；另外两次单独诊断虽然各完成了 60 秒，仍不能使原 B 获得可靠性认证。

新 `B_balanced_2cm` 是另外一份文件，没有覆盖原 B。它**保持原 B 的全部腰部和上肢关节参考不变，只调整 12 个腿关节**：在 MuJoCo 运动学模型中虚拟降低根高度 2cm，求解腿部补偿以保持双足世界位置和姿态。足位置残差约 1.7×10⁻⁸m，足旋转残差约 7.7×10⁻⁹rad；两侧膝参考分别增加约 0.369 / 0.329rad。

这些是几何求解结果，不是动态稳定证明。实际执行没有直接发送世界根位置，仍通过 q/dq 参考交给 SONIC。该候选两次筛查和五次留出站立通过，只支持“这一新参考在本轮静态条件下可运行”，不能说原 B 已修好，也不能证明较低站姿就是历史失败的唯一根因。

新候选采用 A 初始化后以 5 秒五次曲线进入目标，再进行额外落脚稳定检查；原始准备轨迹单独记录在 `preparation.jsonl`。60 秒计时在准备结束之后开始，正式测量期间弹簧关闭且记录的外力为零。

## 耐久具体失败在哪里

A 耐久计划为 324 秒：每 108 秒更换一次模式，依次左臂、右臂、双臂。命令是周期 12 秒、幅度 0.12rad 的肩俯仰和肘角缓慢变化；它属于合成机器人空间命令，不是新真人录制。

该次测量持续约 **145.27 秒**。约 145.06 秒时根高度首次低于 0.75m，随后触发低于 0.65m 的监控退出；退出前最后记录的根高度约 **0.301m**，根水平偏移最大约 **25.82cm**。

视频已经清楚显示机器人倾倒。这次没有触发模型中根高度低于 0.2m 的摔倒重置事件，因此必须区分**实际可见的倾倒**与**模型是否记录 fall/reset 事件**：事件计数为零绝不表示没有倒地。旧事件判定过窄，后续必须增加姿态、躯干接地等判据，并缩短退出延迟。补充姿态审计与原登记结果分开保存，不修改原始日志。原 B 较早那次试验也有明确的 fall 事件。

耐久中的二值双足接触率仍约为 **99.67%**。这直接说明：脚仍接触地面不等于身体稳定，不能只用接触率评价全身可执行性。

链路证据如下：

| 观测 | 结果 | 可以支持什么 |
|---|---:|---|
| 发布间隔 P99 / 最大值（sent_t） | 26.33 / 44.14 ms | 串流整体持续；仍有调度抖动 |
| 调试反馈最大记录间隔 | 121.44 ms | 未出现本次早期 v1 的超过一秒反馈消失 |
| 控制器当前解码目标的最大相邻跳变 | 0.00185 rad | 没有发现大的当前位置目标接缝 |
| 未编辑解码关节偏离基线最大值 | 1.64×10⁻⁸ rad | 腿、腰及未选腕关节的解码参考保持原值 |
| 参考有效标记 | 100% | 当前参考观测持续有效 |
| 编码模式 / 帧步长 | 始终 0 / 1 | 没有观测到模式或步长切换 |
| 本地播放帧为零的次数 | 0 | 未发现该区间反复重置到首帧 |
| 左、右臂模式解码变化范围 | 均约 0.120 rad | 非零编辑确实进入当前参考观测 |

这些结果削弱了“目标冻结、模式切换、大参考跳变是本次首发原因”的解释。它们**没有证明所有未来窗口、策略观测、动作输出、实际下行指令接收和接触动力学都正确**，也不能单凭这些数据就宣布 SONIC 有 bug。控制器调试反馈新鲜，不等于电机目标下行链路也已经逐条核验。

当前最重要的未解决问题是：**这组固定步行帧及手工上肢增量组成的参考，能否被现有冻结跟踪器持续稳定执行，以及失稳前是哪些策略输出、关节力矩与接触量首先发生异常。** 不能把“29 维有限、在关节范围内、经过限速”当作“动力学可执行”。

## 我需要承担的实现与评估问题

1. 我把步行动作的单帧固定成站立基线，又手工构造 B。短时能运行不表示它们就是经过充分资格验证的站立和连续编辑参考。此前从短片成功扩展到长期能力，证据不足。
2. 本轮首次试验启动时，WSL 刚冷启动，局部回环路由的恢复晚于部分连接创建，形成了环境混杂。后续已改为创建任何控制器连接前验证路由及双向 TCP；这次修复不等于解释了全部历史冻结。
3. 新汇总检查返回 NumPy 布尔值，JSON 序列化失败。物理测量已保存；修复只转换布尔值类型，并从原记录恢复，没有重跑或替换该次尝试。离线候选新增姿态检查时再次暴露同类输出错误，已在输出边界显式转换并逐项落盘。修复说明和原协议都保留。
4. 真人离线基准最初将浮点采样恰好到达片尾的正常释放算成异常；已改为明确的有效区间采样，同时单独验证片尾释放，保留了最初结果。
5. 碰撞几何最初遗漏了 29 维参考之外的手指姿态。已用实测的非参考关节重建模型基线；A 的部分参考仍有既有手指与髋部接触，不能将当前结果宣传为“整机参考无碰撞”。

更成熟的工作方式，是把参考资格、传输、当前帧消费、策略输出、实际动力学分段验证。本轮的固定尝试、留出批次和失败停止规则确实阻止了将静态成功误包装成真人全身闭环完成。

## 已准备好的真人路径，尚未物理执行

原有单目视频在双臂、髋、膝、踝同时达到既定置信度时，最长连续片段约 2.6 秒，不适合直接冒充连续全身验证。我没有降低该置信度门槛。

随后准备了 CMU 13_30 的原始光学动捕候选及对应 ASF 骨架。AMC 文件约 1.98MB，已核对独立取得的 Git blob；原始来源、镜像、许可及各文件 SHA256 均保留。采用原始 120Hz 动作，不使用降为 10Hz、仅保留 12 个通道的简化 MAT 数据。CMU 官方格式说明给出了长度单位换算；本实现使用 0.0254/0.45 m/源单位，并验证了骨架层级、连续帧编号及旋转正交性。[CMU 数据库](https://mocap.cs.cmu.edu/)、[CMU 格式说明](https://mocap.cs.cmu.edu/info.php)、[原始动作与标注镜像](https://github.com/michaelchughes/mocap6dataset)。

候选选取原动作 11.8–16.1 秒的下蹲片段，明确以 3 倍慢放回放为 12.9 秒，按源时间戳因果零阶保持。它是真人动捕记录，不是现场摄像头输入；源文件没有提供光学置信度或实测足力，不能编造这些字段。

已实现但未进入物理试验的路径为：

`真人具名骨架 → 接管时人体零点 → 手腕在躯干坐标系中的位移增量 + 骨盆相对踝部的高度变化 → 手部有界 IK + 支撑足位姿保持的腿部姿态表 → 足位姿/模型接触检查和任务缩放 → 连续性编辑器 → SONIC → MuJoCo`

这里选择了一个有限、可审计的分解：腰部和根朝向固定时，手部在躯干内的目标可与腿部降身任务分开求解。腿部离线生成一维降身姿态表，在线插值并重新检查双足位姿；手部在线做有界 IK。它**不是通用全身分层 QP**，不支持改变自主参考、腰部旋转、根水平移动或迈步。后续扩展到这些任务时，应升级统一约束求解，不能继续无条件沿用固定表。

小幅候选的手位移上限为 5cm、虚拟降身上限为 2cm。离线零增量输出严格等于原参考；早期完整回放中，模型接触投影在 A 中约 4% 的更新发生缩放，最大手任务损失约 7.3mm。这些损失必须与跟踪误差分别报告。当前只控制不新增/明显加深模型接触，不能当作消除了基线已有穿透或给出了连续碰撞认证。

最终离线复核没有整体通过：默认数值库进程实测创建 39 个本机线程，已在候选入口固定单线程并保持 20ms 门槛；该配置下 B_balanced 完成 645 个更新，最大映射耗时约 13.01ms，而 A 在第 24 个已接受样本之后遇到一次 **25.29ms** 的计算并按预算退出。因此当前最终离线状态为 **1/2 通过**，A 的最坏观测值必须包含这次失败计算，不能只报告已接受样本的较小最大值。单线程配置不是硬实时保证，也未证明是全部超时的唯一根因。初始姿态失配采用同一躯干坐标中的上臂/前臂方向及肘角共同核验，避免仅凭一个肘角判断整个人体姿态是否相同。

运行入口实际被失败的可靠性门槛拒绝，`human_gate_negative_test.json` 已保存该结果。离线计算通过不等于真人机器人闭环成功。后续 7.5cm/3cm、10cm/4cm 的级别只在前一级物理任务通过后才允许尝试，本轮都没有尝试。

## 当前攻克了什么，创新还差什么

已取得证据的工程进展：独立启动与长时协议可复核；通信接收与应用确认分开；控制器参考有效性和合并窗口可关联；十次候选站立通过；真实耐久失败能定位到具体模式与时间；失败门槛真实阻挡后续运行；真人输入的骨架、单位、因果回放和有限接触保持映射已形成离线候选。

本轮没有获得新的论文级算法结论。接管去重、有界 IK、五次插值和任务投影都是常用技术；有限姿态表也只适用于当前静态任务。潜在研究贡献仍是“人机姿态失配时，相对持续推进的机器人参考进行接触一致的全身增量编辑”。它还需要动态参考、全身任务、真实运行、对照和消融共同支持。

## 下一次最有效的修复路径

1. **先补齐实际执行链并重放失败输入。** 对齐策略输出、电机目标下发与仿真接收的序列/时间、实际关节力矩与饱和、足接触力/压力中心、躯干状态和策略观测。先判断异常出现在策略输出之前、下行接收之间还是接触动力学之后。仅恢复 qpos/qvel 不足以恢复学习控制器的观测历史、动作历史、heading 和流播放状态，不能冒称确定性重放。
2. **同步资格验证参考来源。** 对比当前固定步行帧与官方静止/idle 参考或系统默认站姿，分别记录原始 A/B 和新参考身份。先证明零编辑及既定小幅任务本身可持续，不直接把任意关节正弦当作已知可执行轨迹；也不在缺少执行链证据时通过反复换姿态追求一次通过。
3. **以具体测量选择修复。** 若参考经运动学与接触检查仍不符合支持条件，做任务投影、重平衡或拒绝；若完整合格参考仍导致策略输出发散，再评估控制器分布适配。保留冻结权重作为对照，不先通过加大增益或改仿真参数掩盖失败。
4. **重新预登记验证。** 参考、初始化或跟踪器发生实质修改后，用明确命名的新版本重新做重复与耐久；现有成功和失败仍保留。不能改阈值、删掉失败模式或混用不同版本凑通过次数。
5. **出口通过后恢复已准备好的顺序。** 先真人 5cm/2cm 级别，再在两个合格起点都通过后逐级到 7.5cm/3cm、10cm/4cm。每级同时报告实际幅度、投影损失、足滑、根漂移、失败和视频。

真人候选还需单独修复 A 的求解预算：把耗时求解与 50Hz 发布解耦，显式管理结果年龄、超预算结果丢弃、短时保持及释放；重新核验碰撞投影开销与不可达处理。不能通过把 20ms 阈值改大就宣布实时问题解决。

本轮没有开展新的 54 次矩阵。原 D5/D6 冻结文件仍需随交付校验，原矩阵成绩仍为 39/54；本轮新增筛查和验证不能改写那个成绩。
