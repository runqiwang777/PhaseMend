# 手腿协同里程碑：技术实现、证据与剩余距离

2026-11-19。本报告依据附件 PDF 的目标、现有代码及本次原始物理日志。文中的后续指标属于工程验收建议，不是 PDF 原文要求。

本次达到一个有限但明确的结果：在冻结 SONIC 策略和真实 MuJoCo 动力学下，完成一次站立双手抬升、双腿屈曲、骨盆降低、随后回位并释放的协调动作。预先约定的两次物理尝试为“真人双臂增量基线”和“合成手腿协同探针”，均通过各自的初步门槛；保持期补充审计也支持协同动作确实发生。没有以成功重跑替换失败，没有开展新的 54 次矩阵。

这是单一起点 A 上的一次协同可行性试验，尚未达到“真人实时介入编辑全身自主动作”的最终验收。工程能力有了推进，研究结论仍需后续实验。

## 本次视频如何检查

- `coordination_A_actual.mp4`：本次协同探针的机器人实测状态，两个视角同时显示同一次试验；基线、接管、上升、保持、回位、释放与 AUTO 连续呈现。以日志时间为准，探针时间 0–3 秒渐变，3–7 秒保持，7–10 秒回位，随后结束并释放。
- `reliable_baseline_A_actual.mp4`：本次真人双臂增量回放基线，用于先验证既有能力仍可运行。
- 对应的 `*_full_initialization.mp4` 保留从第一条物理状态起的连续时间，包括初始化悬挂；该补充视频以 2fps 采样、正常时间播放。主要验收片段为 8fps。
- 所有画面由 `sim.jsonl` 中的真实 `qpos` 离线重绘，正常速度，不是现场屏幕录制，也不是把期望动作动画当作实测结果。没有事后拟合时间偏移。主片省略 active_start 之前的加载和悬挂，补充片包含初始化。
- 协同片的输入是合成机器人空间探针；人体录像在这一试验只提供现有驱动器的时间进度。它不能被宣传为真人已经驱动了腰腿。双足保持接触，尚无抬脚、迈步或摆动腿编辑。

建议重点检查：双手上抬是否伴随屈膝降身；双脚是否明显滑移；保持段是否持续；回位和释放是否平顺；画面底部 spring 是否在正式动作前关闭。数值和异常判断仍以原始日志为准。

## 具体实现路径

### 1. 先分清环境故障、命令状态和算法行为

本次遇到新的 WSL 回环故障：最小同进程 TCP 程序也出现监听后连接失败；`ip route get` 显示本机 `127.0.0.1` TCP 优先走 `loopback0` 的虚拟转发路由，而非 Linux 本地路由。仅恢复项目端口 5556–5557、8792–8793 的入向目的端口和返回源端口本地路由后，同进程双向数据传输、HTTP 检查和物理试验都成功。其他端口仍保留原路由。

这是本次环境故障的定位与局部绕行，不足以解释此前全部连接重置。历史中会话摔倒或初始化退出也会导致 API 消失，必须分别读取首发故障日志。没有禁用保护器、扩大初始化门槛或修改 SONIC 权重来换取通过。

局部路由规则是 WSL 当前运行期的修改；没有改全局网络模式、重启整个 WSL 或关闭防火墙。`milestone_network.py --inspect / --apply / --rollback` 保存了检查、重建和精确撤销方法；apply/rollback 需以 WSL root 运行。

### 2. 命令接收和实际应用分开确认

新增隔离模块 `reliable_web.py`、`reliable_control_api.py`、`session_reliable.py`、`reliable_closed_loop.py`，保留此前冻结入口。客户端先生成一次 request_id，重试沿用同一编号；服务端在锁内完成登记和入队，重复编号且内容相同则去重，内容冲突返回 409。接管和释放需要等待状态机实际消费后的确认，并返回消费时刻的锚点和机器人状态，避免把“HTTP 已接收”当成“已经接管”。网络写出前释放状态锁。

“回复丢失后同编号重试、仅应用一次、重复去重、同编号冲突拒绝”四项检查通过。回复丢失测试在单元环境中由假消费者隔离验证，随后真实物理试验验证了接管和释放路径。命令账本仍在内存中，至多 4096 条；没有进程崩溃后的持久化承诺，也没有无限重试承诺。stop 目前仅确认入队，最终结束仍由进程退出和 session 日志核实。

日志中的每次 5 条连接拒绝均来自启动前检查“没有已有会话”，发生在新会话尚未启动时；不能当作编辑期间发生了 5 次断连。相关原始记录保留。

### 3. 真人双臂增量基线

已有路径继续使用：人体录制 → 坐标和尺度标定 → 接管时记录人体零点 h₀ 与机器人当前参考 b(t₀) → 后续人体手部增量 → 当前机器人参考的手部 FK 加增量 → 有界 IK → 连续性编辑器 → 50Hz、51 帧预测窗口 → 冻结 SONIC → MuJoCo。

目标形式为 `p_des(t) = FK_hand(b(t)) + S·(h(t) − h₀)`。它说明增量如何作用于当前参考；本次物理基线的 b(t) 仍为站立常量，不能拿这次结果证明持续运动参考已经解决。

### 4. 手腿协同探针

使用同一 MuJoCo 模型和 29 维关节顺序。离线优化 12 个腿关节及两侧各 4 个肩肘关节：以起始参考的双足世界位置和姿态为目标，把虚拟根高度从 0.80m 改成 0.78m，同时让双手世界高度各增加 0.05m。

求解器为有界 `scipy.optimize.least_squares`，残差权重分别为足位置 20、足旋转 5、手位置 1、关节偏离正则 0.001，最多 120 次函数评估；足位置残差必须小于 3mm。这里是加权软约束加结果检查，尚不是硬约束分层 QP；该入口也未对足旋转设置独立拒绝阈值。

得到关节偏移 Δq 后，在线按五次曲线 `α(u)=10u³−15u⁴+6u⁵` 输出 `q_req(t)=b(t)+α(t)Δq`：3 秒上升、保持至 7 秒、3 秒回位，最后零偏移。全部 29 维经过既有连续性编辑器，使用 1.5rad/s、8rad/s² 参考边界，再送入 SONIC。世界根位置没有直接发送，实际下降完全由腿关节参考与跟踪器/接触动力学共同产生并由日志测量。

本探针在线 IK 耗时记为 0，是因为候选姿态已经离线求出；绝不能把它当作在线全身 IK 已达到实时预算。固定 Δq 的方法也不能保证在变化的 b(t) 下保持足约束，需要后续在线重算与约束求解。

### 5. 闭环审计

分开记录命令应用、发布参考、C++ 接收/合并窗口、解码目标有效性、实测关节、根运动和足接触。独立追踪版控制器只补充观测，不改模型权重。除峰值门槛外，另外计算动作前、保持与回位窗口，检查双膝是否参与以及足端漂移。原 D5/D6 冻结清单再次校验通过，原矩阵仍为 39/54，没有改写历史成绩。

## 已攻克的难点与当前创新边界

已经得到具体证据的工程进展：定位本次 WSL 路由故障；在重试时避免重复应用有副作用的接管命令；把接收确认与消费确认分开；为串流补充可关联观测；把此前“几何上能做”的手腿动作推进为真实动力学中的一次成功执行，并确认释放后可返回 AUTO。

五次插值、有界 IK、相对姿态差分、去重确认本身都是常用技术。本次不能声称已经取得新的全身控制算法或论文级创新。

值得继续验证的研究主线是：**姿态失配条件下，以持续推进的机器人参考为锚，进行具有接触优先级的全身增量编辑，并显式管理接入、失帧和释放的连续性。** 潜在贡献应来自这几个条件共同成立时的效果与机制，而非模块数量。要使其成为可成立的创新点，至少需要动态参考上的绝对映射/关节增量/末端或全身增量对照、相同任务有无接触约束的消融、姿态失配分组、任务保持和失败率证据，以及相关工作比对。当前只有工程实现和待检验假设。

## 当前问题与下一步可能遇到的问题

当前问题：仅一次 A 起点协同、没有 B 起点证据；历史初始化失败和目标冻结机制尚未全面闭环；人体全身输入、在线接触约束求解和移动参考缺失；历史长失帧重采锚 IK 的 P95 约 223ms 仍未解决。环境修复只覆盖本项目端口，重启 WSL 后应重新预检。单次成功不能证明鲁棒性或推广性。

下一步预计最容易出问题的地方：

1. 动作放大后手、足、关节界和支撑会互相冲突；需要投影或拒绝并报告牺牲了哪个任务，不能强行追踪。
2. 单目腿部深度、遮挡和脚接触误判可能直接改变承重腿参考；应先可靠录制/回放，按体段置信度降级，再接实时感知。
3. 自主参考持续推进时，当前速度/加速度界可能与保持原动作冲突；必须区分总参考限制和编辑增量限制，预先规定可行合同。
4. 静态足约束和 CoM 裕度不等于动态稳定；步态需要接触相位和控制器能力边界，不能直接把人体脚位移加到承重脚。
5. 重采锚、碰撞检查及不可达重试可能阻塞 20ms 周期；求解器需明确耗时预算、超时保留/释放策略和独立输出线程。
6. 几何可行但 SONIC 执行差，可能意味着参考超出策略分布；需要先缩小已验证动作域，不能简单增大增益，也不能先断言必须重训。

## 最有效的后续推进顺序

1. **可靠性出口继续补齐。** A/B 独立启动累计 10 次、每次 60 秒；至少三种有效动作累计 10 分钟；针对超时、冻结、无效初始化重复注入，审计误报和恢复。新主矩阵仍不放行。10 次零失败也只是筛查，不是高可靠性认证。
2. **下一个功能里程碑：真人抬手加下蹲的可回放双支撑编辑。** 先取得可信人体全身录制，核验躯干/大腿/小腿旋转与置信度；采用同模型的在线受约束全身求解，先 A/B 小幅，再视执行证据扩到每手 10cm、降身 4cm。这个幅度是待放行目标，不能保证当前控制器可执行。提交真人与机器人连续对照视频、投影残差、足端漂移及失败样本。
3. **持续参考。** 先验证原自主上肢参考无编辑稳定，再检验一侧继续自主运动、另一侧增量编辑，以及被编辑部位自身 base 也在移动的情况。通过后才进入慢踏步参考。释放目标必须是释放时的当前参考。
4. **接触相位和实时输入。** 在可信全身回放通过后引入重心转移和摆动足限制；再把实时相机/动捕换入同一输入协议，报告各段时延与失帧降级。两件事分开验证，避免把感知错误和控制错误混在一起。
5. **最后冻结研究矩阵。** 根据最终动作能力制定动态参考、姿态失配、接触和输入质量对照，报告完成率、条件误差、任务保持、时延、失败及消融。原站立 54 次只在确有价值且门槛通过后重做；它不是 PDF 全身任务的替代验收。
